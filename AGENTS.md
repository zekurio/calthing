# Repository Guidelines

- calthing merges the calendar APIs of any number of Radarr/Sonarr instances into one iCal feed and
  a web calendar. The Deno + Hono backend lives in `src/` (`upstream/` ARR and Jellyfin clients,
  `services/` fetching/caching, iCal rendering, feed tokens, `http/` routes and static serving,
  `config.ts` YAML parsing); the Svelte 5 frontend is in `frontend/src/`; browser-safe DTOs are in
  `shared/api.ts`; tests and fixtures in `tests/`; Nix package, NixOS module, and the dependency
  hash script in `nix/`.
- The default branch is `main` and it is the only long-lived branch; use `main` or `origin/main` for
  diffs.
- Deno 2 is the only toolchain — never use npm, pnpm, yarn, or Bun, and never add a `package.json`.
  Dependencies are pinned in `deno.json` + `deno.lock`; `vendor/` (jsr) and `node_modules/` (npm)
  are generated by `deno install` and never committed.
- Run everything through `deno task`: `dev` (backend `:8080` + Vite `:5173`, or `devenv up`),
  `test`, `check` (`deno check` on `src/ shared/ tests/` plus svelte-check), `frontend:build`,
  `start -config config.yaml`.
- Formatting is `deno fmt` (single quotes, no semicolons, 100 columns) and linting is `deno lint`;
  both exclude `frontend/` and `vendor/`, fmt also skips `tests/fixtures/`. TypeScript is strict
  with `noUncheckedIndexedAccess` and `verbatimModuleSyntax`.
- `deno fmt`, `deno lint`, `deno task check`, and `deno task test` must all pass before a coding
  task is complete.
- After changing dependency versions, run `deno install`, commit `deno.json` and `deno.lock`,
  regenerate `denoDepsHashes` with `nix/update-deps-hashes.sh`, and confirm with `nix build`.
- `tests/fixtures/expected.ics` is compared byte-for-byte; update it only for intentional iCal
  rendering changes.
- Never commit `config.yaml`, `.env`, API keys, or tokens. New config options need parsing plus a
  default in `src/config.ts`, an entry in `config.example.yaml`, and a README mention.
- Instance names are part of event UIDs; renaming one re-creates its events in every subscribed
  calendar. Treat them as stable and preserve UID formats.

## Branch Names

Use a short branch name of at most three words, separated by hyphens. Do not use slashes or type
prefixes such as `feat/` or `fix/`.

Examples: `feed-tokens`, `fix-week-grid`, `add-jellyfin-links`.

## Commits and PR Titles

Use conventional commit-style messages and PR titles: `type(scope): summary`, with `!` for breaking
changes (`feat!: rename to calthing with costthing design and Jellyfin auth`).

Valid types are `feat`, `fix`, `docs`, `chore`, `refactor`, `style`, and `test`. Scopes are
optional; use the affected area when helpful, e.g. `http`, `config`, `ical`, `frontend`, or `nix`.

## Style Guide

### General Principles

- Rely on type inference; annotate exported signatures and public interfaces only.
- Prefer `const` and early returns over reassignment and `else`.
- Keep helpers below the exported function they support, in the module that uses them.
- Comment non-obvious constraints (browser cookie limits, constant-time comparison, UTC handling),
  not obvious assignments.
- Do not extract single-use helpers preemptively; extract when the name adds meaning.

### Imports

Relative imports keep the `.ts` extension, and type-only imports must say so
(`verbatimModuleSyntax`). Never alias or star-import.

```ts
// Good
import type { CalendarEvent } from '../domain/event.ts'
import { fetchCalendar } from '../upstream/client.ts'

// Bad
import * as event from '../domain/event'
import { fetchCalendar as fetchArr } from '../upstream/client'
```

### Errors

Error messages are lowercase and carry the failing context as a prefix. Never throw bare strings or
context-free messages.

```ts
// Good
throw new Error(`instance ${instance.name}: ${path} returned ${response.status}: ${body}`)
throw new Error(`parse config: ${path} must be a mapping`)

// Bad
throw new Error('request failed')
```

### Dependency Injection

Backend modules take collaborators (clock, fetch, auth client) as constructor or option arguments
with production defaults, so tests can substitute fakes without module mocking.

```ts
// Good
constructor(instances: Instance[], ttlMs: number, fetchInstance: ArrFetch = fetchCalendar, now: Clock = () => new Date())

// Bad
constructor(instances: Instance[], ttlMs: number) // reads Date.now() and global fetch internally
```

Class state that is not part of the API uses `#private` fields (see `Fetcher`).

### Svelte

Svelte 5 runes only — `$props`, `$state`, `$derived`, `$effect`; no stores, no `export let`.
Components are `PascalCase` in `frontend/src/components/`; helpers are lower camel case in
`frontend/src/lib/`. Every user-facing string goes through `t()` from `lib/i18n.svelte.ts` and needs
both a `de` and an `en` entry — never hardcode display text in a component.

### Dates

The backend computes in UTC (`utcStartOfDay`, `addUtcDays`) and DTOs carry RFC3339 strings, never
`Date` objects. Locale formatting happens only in `frontend/src/lib/dates.ts`.

## Repo Patterns

- Routes are chained Hono handlers in `src/http/app.ts`, with request validation backed by TypeBox.
  `export type AppType` is imported type-only by the Hono RPC client in `frontend/src/lib/api.ts`,
  so preserve the route chain and return typed responses for every status code.
- Handlers return errors via `context.text('message\n', code, errorHeaders)` (plain text,
  `nosniff`); they never throw. Unsupported methods answer 405 with an `Allow` header.
- All ARR HTTP goes through `getJson` in `src/upstream/client.ts`: `X-Api-Key`, 15s abort timeout,
  error bodies truncated to 512 bytes.
- `Fetcher` is the only upstream entry point: per-instance cache keyed by name + UTC day window,
  in-flight coalescing, failures cached for the same TTL and surfaced as `instances[].error` while
  other instances keep serving. A single instance being down must never fail a request.
- Auth is Jellyfin-backed: the `calthing_session` HttpOnly cookie holds the Jellyfin token and is
  re-validated per request, so revoking in Jellyfin logs the visitor out here. Calendar clients use
  `<userId>.<HMAC-SHA256>` feed tokens from `src/services/tokens.ts`, which grant feed access only.
  Jellyfin `api_key` and the private `url` must never reach the browser.
- `src/config.ts` decodes YAML through `RawConfigSchema`, applies defaults and duration parsing,
  expands `${VAR}` from the environment, and fails loudly on unset references. Extend the schemas
  and parsing helpers instead of adding ad-hoc casts.
- Frontend data loading uses TanStack Query (`createQuery` keyed by `['events', start, end]`) and
  passes the query `AbortSignal` into Hono RPC; no component calls `fetch` directly.
- Tests use `Deno.test` with behavior-sentence names, `t.step` for shared expectations, injected
  fakes, and JSON fixtures in `tests/fixtures/` — never live ARR or Jellyfin services.
- `nix/package.nix` pins an explicit source fileset; new top-level source directories must be added
  to `projectSource` or they are missing from the build.
